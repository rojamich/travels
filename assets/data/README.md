# assets/data — vendored reference data

These files are copies. They are kept in the repo rather than fetched from a
CDN at page load, because a map that draws itself from someone else's GitHub
repo stops drawing the day that repo is renamed, rewritten or deleted — and
the failure is silent: the page loads, the shape layer just never appears.

The same lesson arrived the hard way with the basemap: CARTO served tiles
key-free for years, then began watermarking them. Anything a visitor's browser
must fetch for the page to be right belongs here.

| File | Source | Retrieved |
| ---- | ------ | --------- |
| `world-countries.geo.json` | https://github.com/johan/world.geo.json — `countries.geo.json` | 2026-08-27 |
| `us-states.geo.json` | https://github.com/PublicaMundi/MappingAPI — `data/geojson/us-states.json` | 2026-08-27 |

Both are unmodified. Country shapes are keyed by ISO 3166-1 alpha-3 in the
feature `id`, which is what `code:` in `_data/countries.yml` has to match for a
country to shade on /stats/. Two ids in the world file are not ISO codes:
`CS-KM` (Kosovo, which has no ISO code) and `-99` (used for disputed areas).

Neither file needs updating on a schedule. Borders change rarely, and when one
does, re-download from the source above and check `/admin-stats/` still shows
every country resolving.

`search-index.json` in this folder is different — that one is generated by
Jekyll at build time from the posts, not vendored.
