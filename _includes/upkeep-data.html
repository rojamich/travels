{%- comment -%} ============================================================================= upkeep-data.html — the short list of things nobody computes ============================================================================= Sets two lists, the same length and in the same order: upkeep one alert each: a sentence about hand-kept data that has gone stale or was never filled in, and the rows it is about. An empty list means there is nothing to say. upkeep_keys the keys of that alert's rows, space-separated. /admin-stats/ and the editor's banner both use them to tell which rows she has looked at and set aside. See _plugins/upkeep_key.rb. Almost everything on this site is computed from the posts and trips on every build, so it can't quietly go wrong. A few files aren't — the status bar, the personal bests, the flags — and a stale one looks exactly like a fresh one. This is what notices. REQUIRES `visited_countries`, so include country-data.html first. Included by: _pages/admin-stats.html renders it as the "Needs a human" panel admin-upkeep.json the same list as JSON, which /admin/ fetches to put a quiet banner in the editor (repo root, so it escapes the layout every _pages/ file inherits) Both read this one file, so the editor's banner and the dashboard can never say different things. SET ASIDE, ONE ROW AT A TIME Most of these alerts are a sentence and a list: nine posts with no map pin, four countries with no flag. Some of those rows are answers rather than problems — a letter home has no pin and never will — so every row carries a key of its own and can be set aside on its own. That one goes quiet; the eight beside it keep asking, and a tenth that turns up next week arrives unread. Which makes the key the thing to get right. It has to name THAT ROW and nothing else: the post's url, the country, the title of the record. Build it from the length of the list the row sits in and setting one aside would silence the lot; build it from anything that moves on its own, like a number of days, and every morning would bring it back. WHAT /admin-stats/ LOOKS FOR Keep the prose to and — the JSON version strips tags — and use these where they help:
    the rows, each an
  • . The page hangs the set-aside button off that key, so nothing here draws a button itself. data-upkeep-n holds the number of rows still asking. The page keeps it right as she sets them aside. data-upkeep-plural="a|b" "a" when that number is 1, "b" when it isn't. Write the plural form as the tag's own text; it only shows before the page has had its say. data-upkeep-group a heading — a trip, say — that should disappear once every row underneath it has gone quiet. An alert that is one fact rather than a list, like the status bar, wraps its sentence in a and is set aside whole. There is no special case for it: it is a one-row alert. Prefer a sentence that reads the same whatever the number is. Every plural you spell out is a second copy of the sentence to keep in step, and the row list underneath already says which ones and how many. ADDING A CHECK: work it out here from data that already exists, push the sentence onto `upkeep`, and push its row keys, space-separated, onto `upkeep_keys`. The two lists are read by position, so a check that adds one and not the other leaves every alert below it answering to the wrong name. Don't add a check that needs its own copy of something the site already knows — a reminder that drifts is worse than no reminder. ============================================================================= {%- endcomment -%} {%- assign upkeep = "" | split: "," -%} {%- assign upkeep_keys = "" | split: "," -%} {%- comment -%} The status bar: right until they move, then wrong and silent. {%- endcomment -%} {%- assign here = site.data.status.current_location | default: "" -%} {%- comment -%} Nested rather than one `and` chain on purpose: Liquid evaluates `and` right to left, so the comparison would run before the check that there is anything to compare, and comparing nil to a number is an error rather than a false.
